SQL 분류 . DDL . DCL

1. SQL 의 분류 : DDL . DML . DCL          
SQL 은 데이터베이스와 대화하는 언어. 무엇을 다루느냐에 따라 세 가지로 나뉨. 데이블이라는 그릇의 모양을 만들고 고치고 버리는 명령이 DDL, 
그릇에 담긴 데이터를 조회, 삽입, 수정, 삭제하는 명령이 DML, 누가 무엇을 할 수 있는지 권한과 작업의 확정, 취소를 다루는 명령이 DCL

* DDL(Data Definition Language, 데이터 정의어) : 논리적 . 물리적 데이터 구조 정의 -> CREATE . ALTER . DROP
  + 대상 객체 : DOMAIN . SCHEMA . TABLE . VIEW . INDEX
* DML(Data Manipulation Language, 데이터 조작어) : 데이터 검색 . 삽입 . 수정 . 삭제 -> SELECT . INSERT . UPDATE . DELETE
* DCL(Data Control Language, 데이터 제어어) : 데이터 보안 . 복구 . 병행 수행 제어 . 무결성 유지 -> GRANT . REVOKE . COMMIT . ROLLBACK
  + COMMIT . ROLLBACK . SAVEPOINT 따로 TCL(트랜잭션 제어어)로 분류하기도 함

2. CREATE TABLE 과 제약조건       
테이블을 만들 때는 칼럼 이름과 자료형뿐 아니라, 잘못된 데이터가 들어오지 못하게 막는 제약조건도 함께 정함. 제약조건은 칼럼 옆에 바로 쓰거나(칼럼 수준), 칼럼을 모두 쓴 뒤 CONSTRAINT 이름을
붙여 따로 쓸 수 있음(테이블 수준). 2과목의 키와 무결성이 SQL 로 구현되는 부분

create table 직원(         
    직원코드 int primary key, -- 기본키            
    직원 명 varchar(20) not null, -- 빈 값 금지           
    이메일 varchar(40) unique, -- 중복 금지          
    나이 int check (나이 >= 18), -- 조건 검사        
    직급 varchar(10) default '사원', -- 기본 값           
    부서코드 int,              
    constraint 직원_fk foreign key (부서코드)          
        references 부서(부서코드)             
        on delete cascade  -- 부모 삭제 시 함께 삭제          
)       

제약 조건                  | 의미      
primary key              | 기본키 -> null . 중복 불가(개체 무결성)             
foreign key              | 외래키 -> 다른 테이블(부모)의 기본키 값만 허용(참조 무결성)            
unique / not null        | 중복 값 금지 / null 금지           
check                    | 입력 값이 조건식을 만족해야 함(도메인 무결성)           
default                  | 값을 넣지 않으면 자동으로 들어갈 기본값          
constraint 이름           | 제약조건에 이름을 붙임 -> 나중에 이름으로 수정 . 삭제         

3. DOMAIN . INDEX . VIEW . ALTER . DROP         
CREATE 는 데이블 말고도 여러 객체를 만듦. 값의 범위를 미리 정해 두는 도메인, 검색을 빠르게 하는 인덱스, 자주 쓰는 조회를 저장해 둔 가상 테이블 부가 대표적.
만든 뒤 구조를 바꿀 때는 ALTER, 없앨 때는 DROP

create domain season as varchar(6)             
    check (value in ('spring', 'summer', 'autumn', 'winter'));          
create index idx_name on 학생(name);             
create view 컴공학생 as select 학번, 이름 from 학생 where 학과 = '컴공';            

alter table 학생 add 주소 varchar(20);   -- 칼럼 추가             
alter table 학생 modify 주소 varchar(50);   -- 칼럼 변경(dbms 에 따라 alter column)           
alter table 학생 drop column 주소;  -- 칼럼 삭제           

drop view 컴공학생 cascade;  -- 참조하는 개체까지 함께 제거             
drop table 학생 restrict;  -- 다른 개체가 참조 중이면 제거 취소      

* create domain : 칼럼에 쓸 자료형 + 허용 값(check)을 미리 정의 -> 여러 테이블에서 재사용
* create index : create index 인덱스명 on 테이블(칼럼) -> 검색 속도 향상
* alter table : add(추가) . modify / alter(변경) . drop(삭제)로 테이블 구조 변경
* drop 옵션 : cascade = 참조하는 모든 개체 함께 제거 / restrict = 다른 개체가 참조하면 제거 취소

4. 외래키와 cascade 따라가기               
외래키에 on delete cascade 를 붙이면 부모 테이블의 행이 지워질 때 그 값을 참조하던 자식 테이블의 행도 자동으로 함께 지워짐. 
핵심은 count 가 "행의 개수"를 센다는 점과, 부모 삭제가 자식에게도 번진다는 점.

-- 1번        
select distinct count(부서코드) from 직원 where 부서코드 = 20;             
-- 2번            
delete from 부서 where 부서코드 = 20;           
select distinct(부서코드) from 직원;           

* 1번 : 부서코드가 20인 직원 행 =3개 -> count 결과 3(distinct 는 count 결과 한 줄에 붙어 있어 아무 영향 없음)
* 2번 : 부서 20 삭제 -> cascade 로 직원 3000 . 4000 . 5000 도 삭제 -> 남은 직원 4명 -> 결과 4
* 다른 옵션 : on delete set null(자식 외래키를 null 로) . 옵션이 없거나 restrict 면 자식이 있는 부모는 삭제 거부

5. 권한 제어 : grant . revoke    
데이터베이스는 여러 사람이 함게 쓰기 때문에 누가 어떤 테이블에 무엇을 할 수 있는지 정해야 함. 권한을 주는 명령이 grant, 빼앗는 명령이 revoke.
임의적 접근 통제(DAC)가 바로 이 명령으로 구현

grant 권한리스트 on 개체 to 사용자 [with grant option];
revoke [grant option for] 권한리스트 on 개체 from 사용자 [cascade];

grant select, update on 학생 to 김철수 with grant option;
revoke update on 학생 from 김철수 cascade;

* grant : 데이터베이스 사용자에게 사용 권한 부여(접속 . 객체 생성 . DBA 권한 등)
  + with grant option : 부여받은 권한을 다른 사용자에게 다시 부여할 수 있는 권한까지 줌
* revoke : 사용자의 사용 권한 취소
  + grant option for : 권한은 두고 다른 사용자에게 부여할 수 있는 권한만 취소
  + cascade : 그 사용자가 남에게 준 권한까지 연쇄 취소
* 권한 종류 : select . insert . update . delete . all 등

6. 트랜잭션 제어 : commit . rollback      
여러 SQL을 하나의 작업 단위(트랜잭션)로 묶어 처리할 때, 끝까지 성공하면 확정 중간에 문제가 생기면 통째로 되롤려야함. 확정이 commit, 되돌리기가 rollback,
전부가 아니라 중간 지점까지만 되돌리고 싶을 때 savepoint 로 표시를 남겨 둠

* commit : 수행된 결과를 실제 물리적 디스크에 저장하고 작업 정상 완료를 통보
* rollback : commit 되지 않은 작업을 취소하고 이전 상태로 원복
* savepoint : 트랜잭션 안에 rollback 할 저장 위치를 지정 -> rollback to 저장점

insert into 학생 values(1, '가');           
savepoint a;            
update 학생 set 이름 = '나' where 학번 = 1;          
rollback to a; -- update 만 취소, insert 는 유지          
commit;  -- insert 확정         



DML : INSERT . UPDATE . DELETE

1. dml 한눈에 보기와 작성 규칙        
dml 네 명령은 모두 "어느 테이블의 어떤 행을 어떻게"라는 구조. 조회만 하는 select 를 빼면, 나머지 셋은 데이터를 실제로 바꾸는 명령이라
where 조건을 빠뜨리면 테이블 전체가 바뀌거나 지워지니 특히 조심해야 함.

명령    | 기본 형식       
select | select 칼럼 from 테이블[where 조건];        
insert | insert into 테이블(칼럼 ..) values(값 ..);           
update | update 테이블 set 칼럼 = 값[where 조건];            
delete | delete from 테이블[where 조건];           

* 문자열 . 날짜 : 값에는 작은 따옴표('') -> '라이언, '010-1234-5678'/ 숫자는 따옴표 없이 -> 1, 1415245
* 칼럼(속성)명 : 따옴표를 붙이지 않음 -> where 이름 = '지영'(o) / where '이름' = '지영'(x)
* where 생량 : update . delete 에서 where 가 없으면 모든 행이 대상
* 마무리 : 명령 끝의 세미콜론(;)은 시엄에서 대개 생략 가능 . 키워드의 대소문자는 구분하지 않음

2. insert : 행 삽입          
insert 는 테이블에 새로운 행을 추가. 넣을 칼럼 목록과 값 목록을 같은 순서 . 같은 개수로 짝지어 쓰는 게 기본. 모든 칼럼에 값을 넣을 때는
칼럼 목록을 생략할 수 있고, 다른 테이블에서 조회한 결과를 한꺼번에 넣을 수 있음

-- 1. 칼럼을 지정해 삽입            
insert into 학생(학번, 이름, 학년, 과목, 연락처)          
values (1415245, '라이언', 2, '수학', '010-1234-5678');            

-- 2. 모든 칼럼에 넣을 때는 칼럼 목록 생략 가능(테이블 정의 순서대로)             
insert into 학생 values (1415246, '어피치', 1, '영어', '010-1111-2222');         

-- 3. 일부 칼럼만 -> 나머지는 null 또는 default 값           
insert into 학생(학번, 이름) values (1415247, '무지');           

-- 4. 조회 결과를 삽입 (insert .. select values 없음)           
insert into 우수학생(학번, 이름)            
select 학번, 이름 from 학생 where 학년 = 2;       

3. update : 값 수정      
update 는 이미 있는 행의 값을 바꿈. set 뒤에 "칼럼 = 새 값"을 쓰고, 여러 칼럼은 쉼표로 이음. 새 값 자리에는 계산식도 쓸 수 있어서 "점수를 5점 올려라" 같은 처리도
한 줄이면 됨. 어떤 행을 바꿀지는 where 로 정함

-- 1. 조건에 맞는 행의 값 수정        
update 학생 set 과목평가 = 'A' where 점수 >= 90;       

-- 2. 여러 칼럼 . 계산식      
update 학생 set 점수 = 점수 + 5, 비고 = '가산' where 학년 = 3;       

-- 3. where 생략 -> 모든 행 수정     
update 학생 set 비고 = '확인';           

* 형식 : update 테이블 set 칼럼1 = 값1[, 칼럼2 = 값2 ..] [where 조건] -> from . into 없음
* 자주 하는 실수 : set 대신 values 를 쓰거나, 비교용 where 조건과 대입용 set 식을 헷갈림

4. delete 와 truncate . drop 비교              
delete 는 조건에 맞는 행을 지움. 테이블 자체는 그대로 남음. 비슷해 보이지만 모든 행을 한꺼번에 비우는 truncate, 테이블 구조까지 없애는 drop 은 ddl 명령이라
성격이 다름. 

-- 1. 조건에 맞는 행 삭제             
delete from 학생 where 이름 ='민수';              
-- 2. where 생략 -> 모든 행 삭제(데이블 구조는 남음)              
delete from 학생;              

- delete(DML) : 조건에 맞는 행 삭제(where 생략 시 전체 행) . 구조 유지 / rollback 가능
- truncate(DDL) : 테이블의 모든 행을 한 번에 삭제 . 구조 유지 . 빠름 / 대부분 불가
- drop(DDL) : 테이블 자체(구조 + 데이터) 삭



select 기본과 조건식

1. select 구조와 처리 순서        
select 는 "어느 테이블에서(from) 어떤 행을 골라(where) 무엇을 보여줄지(select)"를 적는 문장. 쓰는 순서와 데이터베이스가 실제로 처리하는 순서가 달라서, 
처리 순서를 알아두면 "왜 where 별칭이나 집계 함수를 못 쓰는지" 같은 문제가 쉽게 풀림

select [distinct] 칼럼1, 칼럼2 [as 별칭] | *         
from 테이블         
[where 행 조건]          
[group by 칼럼 [having 그룹 조건]]             
[order by 칼럼[asc |desc]];          

2. 비교 . 논리 연산자와 우선순위         
where 절에는 비교 연산자(=, <>, >, >=, <, <=)로 조건을 만들고, 여러 조건은 논리 연산자로 이음. 여기서 함정은 AND 가 OR 보다 먼저 계산된다는 점.
수학에서 곱셈을 덧셈보다 먼저하는 것처럼 괄호가 없으면 AND 로 붂인 부분부터 처리

- 비교 : =(같다), <>(다르다), >, >=, <, <=
- 논리(우선순위) : not -> and -> or 순서로 계산, 헷갈리면 괄호로 먼저 묶기

select count(*) from 급여         
where empno > 100 and sal >= 3000 or empno = 200;            
-- 실제 해석 : (empno > 100 and sal >=3000) or (empno = 200)           

* 풀이 : 100 -> 둘 다 거짓 / 200 -> 참 / 300 -> sal 1500이라 and 거짓, empno 도 200이 아님 -> 결과 1
* 괄호의 힘 : [학생]에서 where 학년 = 3 or 학년 4 and 학과 = '컴퓨터' -> 3행 / where (학년 = 3 or 학년 = 4) and 학과 = '컴퓨터' -> 2행

3. in . between . is null       
조건을 or로 길게 늘어놓는 대신 짧게 쓰느 연산자들이 있음. 목록 중 하나와 같으면 in, 범위 안이면 between. 그리고 값이 비어 있는 null 은 "알 수 없는 값"이라 = 로 
비교할 수 없어서 반드시 is null 로 찾음.

4. like 패턴 : % 와 _          
이름이 '이'로 시작하는 사람처럼 글자 모양으로 찾을 때는 like 를 사용. 두 개의 만능 문자를 기억하면 됨. %는 "아무 글자나 몇 글자든(0글자 포함)",
_(언더바)는 "아무 글자나 딱 한 글자"



DISTINCT . 정렬 . 그룹 . 집계

1. distinct : 중복 제거            
select 는 기본적으로 조건에 맞는 모든 행을 보여줌. 같은 값이 여러 번 나와도 그대로 다 나옴. distinct 를 붙이면 중복된 행을 하나로 합쳐 보여줌.

* distinct : 중복 레코드를 제거한 조회 결과 출력  -> select 바로 뒤에 씀
* 함정 : select distinct count(..)처럼 distinct 가 count 바깥에 있으면 결과 한 줄에 붙어 아무 효과 없음

2. order by : 정렬        
결과의 순서를 정하는 절 asc(오름차순, 작은 값 -> 큰 값)가 기본이라 생략할 수 있고, 큰 값부터 보려면 desc(내림차순)를 붙임. 기준을 여러 개 쓰면
첫 번째 기준이 같을 때 두 번째 기준으로 정렬. order by는 select 문의 맨 마지막에 옴

* asc(Ascending) : 오름차순 -> 기본값, 생략 가능 / desc(descending) : 내림차순
* 다중 정렬 : order by 칼럼1[asc|desc], 칼럼2[asc|desc] ... -> 앞 기준이 같을 때만 뒤 기준 적용
* 칼럼 번호 : order by 2 desc -> select 목록의 두 번째 칼럼 기준

3. 집계 함수와 null 처리         
집계 함수는 여러 행을 모아 값 하나로 요약. 여기서 가장 많이 틀리는게 null. count(*) 는 행 자체를 세지만 count(칼럼) . sum . avg 같은 함수는 그 칼럼이 null인 행
을 빼고 계산.

4. group by . having           
과목별 평균, 학과별 인원처럼 그룹마다 집계하려면 group by로 묶음. 그리고 그 겨로가 중 "평균이 90 이상인 그룹만"처럼 구룹에 조건을 걸 때는
where 가 아니라 having 을 씀. where 는 묶기 전 행을 거르고, having 은 묶은 후 그룹을 거름

- where : 그룹으로 묶기 전의 행 / 집계함수 : 사용불가
- having : group by 로 묶은 후의 그룹 / 집계 함수 : 사용 가능(avg(점수) >= 90)



집합 연산과 CROSS JOIN

1. 집합 연산자 : UNION . INTERSECT . EXCEPT              
select 결과는 행들의 집합이라서, 두 결과를 집합처럼 계산할 수 있음. 둘을 합치면 union, 양쪽에 모두 있는 것만 남기면 intersect, 앞 결과ㅔ서 뒤 결과를 빼면
except(오라클에서는 minus). 기본적으로 결과의 중복은 제거

2. 집합 연산의 규칙과 union all           
두 결과를 위아래로 이어 붙이는 연산, 양쪽 select 의 칼럼 개수와 자료형(순서)이 같아야 함. 정렬은 각 select 마다 하지않고 맨 마지막에 한 번만 
order by를 씀. 또 union 은 중복을 없애느라 정렬 . 비교 작업을 하지만, union all 은 그대로 이어 붙이기만 해서 더 빠름

* 규칙 1 : 각 select 의 칼럼 개수가 같고, 대응하는 칼럼의 자료형이 호환되어야 함
* 규칙 2 : 결과 칼럼 이름은 첫 번째 select 의 이름을 따름
* 규칙 3 : order by 는 마지막 select 뒤에 한 번만 사용
* union all : 중복 제거 과정이 없어 빠름 -> 중복이 없다고 확실할 때 사용

3. cross join : 모든 행의 짝             
cross join 은 조건 없이 한 테이블의 모든 행을 다른 테이블의 모든 행과 하나씩 짝지음. 그래서 결과 행 수는 두 테이블 행 수의 곱. 관계 대수의
카티션 곱(교차곱)과 같고, 이렇게 모든 조합을 만든 뒤 where 로 원하는 짝만 고르는 식으로 자주 사용

* 행 수 (카디널리티) : A의 행 수  x B의 행 수
* 칼럼 수(차수) : A의 칼럼 수 + B의 칼럼 수 
* 조인과의 관계 : CROSS JOIN 에 on / where 조건을 걸어 짝을 고르면 일반 조인이 됨



내부 조인과 외부 조인

1. 조인과 inner join        
데이터는 중복을 줄이려고 여러 테이블에 나눠 저장. 그래서 "학생 이름과 학과명"을 함께 보려면 두 테이블을 공통 칼럼(학과코드)으로 다시 이어 붙여야 함.
이게 조인이고, 양쪽에 짝이 있는 행만 남기는 가장 기본적인 조인이 inner join

* 테이블 별칭 : from 학생 s -> s.이름처럼 별칭.칼럼으로 어느 테이블 칼럼인지 구분(AS 생략가능)
* 동등 조인 : =조건으로 잇는 조인 . 같은 이름 칼럼을 자동으로 잇고 한 번만 표시하면 자연 조인(NATURAL JOIN)

2. 외부 조인 : LEFT . RIGHT . FULL               
inner join 은 짝이 없는 행을 버리지만, "학과가 없는 학생도 명단에는 보여줘"처럼 한쪽 테이블의 행을 모두 살리고 싶을 때가 있음. 이때
외부 조인을 사용. 기준이 되는 쪽(left 면 왼쪽, right 면 오른쪽)은 전부 나오고, 짝이 없는 상대편 칼럼은 null 로 채워짐

* left outer join : 왼쪽 테이블의 모든 행 + 짝 -> 짝 없는 오른쪽 칼럼은 null
* right outer join : 오른쪽 테이블의 모든 행 + 짝 -> a right join b = b left join a
* full outer join : 양쪽 모든 행(=left 결과 u right 결과) . outer 는 생략 가능



서브쿼리 기본

1. 서브쿼리의 구조와 종류           
"H회사 제품 중 가장 비싼 것보다 비싼 제품"처럼 조건 자체를 먼저 계산해야 할 때, 그 계산을 괄호 안 select 로 적음. 이것이 서브쿼리.
기본적으로 안쪽이 먼저 실행, 그 결과가 바깥 쿼리의 조건 값으로 들어감. 서브쿼리가 돌려주는 행의 개수에 따라 쓸 수 있는 연산자가 다름

- 단일행 서브쿼리 : (1행; 값 하나) / 함께 쓰는 연산자 : = . <> . > . >= . < . <=
- 다중행 서브쿼리 : (여러 행) / 함께 쓰는 연산자 : in . not in . all . any(some) . exists

* 위치 : where . having(조건), from 절(인라인 뷰 = 임시 테이블), select 절(스칼라 서브쿼리)
* 규칙 : 반드시 괄호로 감쌈 . 단일행 연산자(=)에 여러 행이 돌아오면 오류 -> in을 써야함
