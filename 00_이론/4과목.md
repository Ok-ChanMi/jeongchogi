프로토콜과 흐름, 오류제어

1. 프로토콜(Protocol)
한국 사람과 프랑스 사람이 대화하려면 같은 언어, 같은 대화 예절이 필요
컴퓨터도 마찬가지로 무엇을, 어떻게 언제 주고 받을지 미리 정한 약속이 있어야 통신할 수 있음
이 통신 규약이 프로토콜 핵심은 구문 . 의미 . 순서 세가지 요소

* 프로토콜: 정보 교환을 위해 무엇을, 어떻게, 언제 통신할 지를 정한 통신 규약
  + 메시지를 전달하고 정상 도착 여부를 확인하며 도착하지 않으면 재전송하는 일련의 방법을 정의
* 주요 기능 : 흐름 제어(전송량 . 속도 조정), 동기화(송수신 상태 일치), 오류제어(오류 검출 . 정정)
  + 그 밖에 단편화와 재조립 . 캡슐화 . 연결제어 . 주소 지정 . 다중화 . 순서 제어

> 프로토콜 기본 요소
 요소            | 질문            | 대화로 치면
 구문(Syntax)    | 무엇을?          |  어떤 문법, 글자로 쓸지(데이터 형식)
 의미(Semantics) | 어떻게?          | 각 단어가 무슨 뜻인지(제어 정보)
 순서(Timing)    | 언제?           | 말하는 순서, 속도(타이밍)

2. 흐름제어(Flow control)
- 송신 측이 너무 빠르게 보내면 수신 측의 버퍼가 넘쳐 데이터를 잃어버림, 흐름 제어는 수신 측이 감당할 수 있는 만큼만 보내도록 전송량과 속도를 조절하는 기능
- 하나 보내고 확인 받는 Stop and Wait와 여러 개를 연속으로 보내는 Sliding Window가 대표적

* Stop and Wait : 수신 측의 확인(ACK)을 받은 뒤 다음 패킷을 전송 -> 한번에 하나의 패킷만 전송(단순하지만 느림)
* Sliding Window : 확인 신호를 받지 않고도 미리 정한 윈도우 크기만큼 여러 패킷을 연속 전송 -> 전송 효율 ^
  + 긍정 수신(ACK) 시 윈도우 크기 증가, 부정 신호(NAK) 시 윈도우 크기 감소

3. 혼잡제어(Congesion Control)
흐름 제어가 송신자와 수신자 둘 사이으이 속도 조절이라면 혼잡제어는 네트워크 전체가 막히지 않게 조절하는 기능
TCP는 처음에 조심스럽게 조금 보내다가 빠르게 늘리고(Slow Start), 어느정도 커지면 천천히 늘리며(혼잡 회피), 혼잡이 생기면 다시 줄임

* Slow Start : 정상 전송 시 혼잡 윈도우를 패킷(ACK)마다 1씩 증가 -> 결과적으로 한 주기 마다 2배(지수)로 커짐, 혼잡이 발생하면 윈도우를 1로 줄임
* 혼잡 회피(Congesion Avoidance) : 임계값 이후 윈도우를 선형(1씩)으로 천천히 늘려 트래픽 붕괴를 막는 제어

4. 오류 제어 방식 : FEC와 BEC
전송 중 잡음 때문에 0이 1로 바뀌는 오류가 생길 수 있음, 대응 방법은 두 가지
여분 비트를 넉넉히 실어 보내 수신 측이 스스로 고치는 방식(FEC)과, 오류를 찾기만 하고 다시 보내 달라고 요청하는 방식(BEC)
실시간 방송처럼 재전송이 어려우면 -> FEC
일반 데이터 통신 -> BRC를 주로 사용

* FEC(Forward Error Correction, 전진 오류 수정) : 수신 측이 스스로 오류를 검출하고 수정까지 하는 방식(송신 측에 통보 x)
  + 부가 정보(Redundancy)를 첨가해 전송
    ex) 해밍코드, 상승코드, 재전송 요구가 없어 연속 전송 가능
* BEC(Backward Error Correction, 후진 오류 수정) : 오류가 발생하면 송신 측에 재전송을 요구하는 방식
  + 오류 검출 방식 : 패리티 검사, CRC, 블록 합, 재전송 방법 : ARQ(Stop and Wait ARQ . Go-Back-N . Selective Repeat)

5. 오류 검출 . 정정 코드
오류를 찾으려면 데이터에 검사용 비트를 덧붙여야 함
1비트만 붙이는 패리티는 간단하지만 짝 수 개 오류를 놓치고, 다항식 나눗셈을 쓰는 CRC는 연속으로 생기는 집단 오류까지 잘 찾음, 해밍 코드는 더 나아가 1비트 오류의 비치까지 찾아 고침

* 패리티 검사 : 7~8비트 데이터 블록 끝에 패리티 비트 1개(짝수 / 홀수)를 추가해 1의 개수로 오류 검출
  + ex) 짝수 패리티 1011001 -> 1이 4개(짝수) -> 패리티 0 . 짝수 개 비트 오류는 검출 불가
* 블록 합(Block Sum) : 데이터 블록에 수평, 수직 패리티를 모두 추가 -> 패리티의 약점을 보완
* CRC(순환 중복 검사) : 생성 다항식으로 나눈 나머지를 검사값(FCS, Frame Check Sequence)으로 붙여 전송 -> 집단 오류 검충에 강함
* 해밍 코드 : 여러 개의 검사 비트로 오류를 검출하고 1비트 오류를 스스로 수정(FEC)
  + 해밍 거리 : 두 코드에서 서로 다른 비트 수 . 검출 가능한 최대 오류 수 = 해밍거리 -1
* 상승 코드 : 순차적 디코딩 . 한계값 디코딩을 사용해 여러 비트의 오류를 수정(FEC)
