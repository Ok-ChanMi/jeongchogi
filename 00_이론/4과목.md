프로토콜과 흐름, 오류제어

1. 프로토콜(Protocol)
한국 사람과 프랑스 사람이 대화하려면 같은 언어, 같은 대화 예절이 필요
컴퓨터도 마찬가지로 무엇을, 어떻게 언제 주고 받을지 미리 정한 약속이 있어야 통신할 수 있음
이 통신 규약이 프로토콜 핵심은 구문 . 의미 . 순서 세가지 요소

* 프로토콜: 정보 교환을 위해 무엇을, 어떻게, 언제 통신할 지를 정한 통신 규약
  + 메시지를 전달하고 정상 도착 여부를 확인하며 도착하지 않으면 재전송하는 일련의 방법을 정의
* 주요 기능 : 흐름 제어(전송량 . 속도 조정), 동기화(송수신 상태 일치), 오류제어(오류 검출 . 정정)
  + 그 밖에 단편화와 재조립 . 캡슐화 . 연결제어 . 주소 지정 . 다중화 . 순서 제어

> 프로토콜 기본 요소
 요소            | 질문            | 대화로 치면
 구문(Syntax)    | 무엇을?          |  어떤 문법, 글자로 쓸지(데이터 형식)
 의미(Semantics) | 어떻게?          | 각 단어가 무슨 뜻인지(제어 정보)
 순서(Timing)    | 언제?           | 말하는 순서, 속도(타이밍)

2. 흐름제어(Flow control)
- 송신 측이 너무 빠르게 보내면 수신 측의 버퍼가 넘쳐 데이터를 잃어버림, 흐름 제어는 수신 측이 감당할 수 있는 만큼만 보내도록 전송량과 속도를 조절하는 기능
- 하나 보내고 확인 받는 Stop and Wait와 여러 개를 연속으로 보내는 Sliding Window가 대표적

* Stop and Wait : 수신 측의 확인(ACK)을 받은 뒤 다음 패킷을 전송 -> 한번에 하나의 패킷만 전송(단순하지만 느림)
* Sliding Window : 확인 신호를 받지 않고도 미리 정한 윈도우 크기만큼 여러 패킷을 연속 전송 -> 전송 효율 ^
  + 긍정 수신(ACK) 시 윈도우 크기 증가, 부정 신호(NAK) 시 윈도우 크기 감소

3. 혼잡제어(Congesion Control)
흐름 제어가 송신자와 수신자 둘 사이으이 속도 조절이라면 혼잡제어는 네트워크 전체가 막히지 않게 조절하는 기능
TCP는 처음에 조심스럽게 조금 보내다가 빠르게 늘리고(Slow Start), 어느정도 커지면 천천히 늘리며(혼잡 회피), 혼잡이 생기면 다시 줄임

* Slow Start : 정상 전송 시 혼잡 윈도우를 패킷(ACK)마다 1씩 증가 -> 결과적으로 한 주기 마다 2배(지수)로 커짐, 혼잡이 발생하면 윈도우를 1로 줄임
* 혼잡 회피(Congesion Avoidance) : 임계값 이후 윈도우를 선형(1씩)으로 천천히 늘려 트래픽 붕괴를 막는 제어

4. 오류 제어 방식 : FEC와 BEC
전송 중 잡음 때문에 0이 1로 바뀌는 오류가 생길 수 있음, 대응 방법은 두 가지
여분 비트를 넉넉히 실어 보내 수신 측이 스스로 고치는 방식(FEC)과, 오류를 찾기만 하고 다시 보내 달라고 요청하는 방식(BEC)
실시간 방송처럼 재전송이 어려우면 -> FEC
일반 데이터 통신 -> BRC를 주로 사용

* FEC(Forward Error Correction, 전진 오류 수정) : 수신 측이 스스로 오류를 검출하고 수정까지 하는 방식(송신 측에 통보 x)
  + 부가 정보(Redundancy)를 첨가해 전송
    ex) 해밍코드, 상승코드, 재전송 요구가 없어 연속 전송 가능
* BEC(Backward Error Correction, 후진 오류 수정) : 오류가 발생하면 송신 측에 재전송을 요구하는 방식
  + 오류 검출 방식 : 패리티 검사, CRC, 블록 합, 재전송 방법 : ARQ(Stop and Wait ARQ . Go-Back-N . Selective Repeat)

5. 오류 검출 . 정정 코드
오류를 찾으려면 데이터에 검사용 비트를 덧붙여야 함
1비트만 붙이는 패리티는 간단하지만 짝 수 개 오류를 놓치고, 다항식 나눗셈을 쓰는 CRC는 연속으로 생기는 집단 오류까지 잘 찾음, 해밍 코드는 더 나아가 1비트 오류의 비치까지 찾아 고침

* 패리티 검사 : 7~8비트 데이터 블록 끝에 패리티 비트 1개(짝수 / 홀수)를 추가해 1의 개수로 오류 검출
  + ex) 짝수 패리티 1011001 -> 1이 4개(짝수) -> 패리티 0 . 짝수 개 비트 오류는 검출 불가
* 블록 합(Block Sum) : 데이터 블록에 수평, 수직 패리티를 모두 추가 -> 패리티의 약점을 보완
* CRC(순환 중복 검사) : 생성 다항식으로 나눈 나머지를 검사값(FCS, Frame Check Sequence)으로 붙여 전송 -> 집단 오류 검충에 강함
* 해밍 코드 : 여러 개의 검사 비트로 오류를 검출하고 1비트 오류를 스스로 수정(FEC)
  + 해밍 거리 : 두 코드에서 서로 다른 비트 수 . 검출 가능한 최대 오류 수 = 해밍거리 -1
* 상승 코드 : 순차적 디코딩 . 한계값 디코딩을 사용해 여러 비트의 오류를 수정(FEC)


IP주소와 LAN 기술

1. IPv4와 IPv6
- IP 주소는 네트워크에 연결된 장치마다 붙는 고유한 주소
- 지금 널리 쓰는 IPv4는 32비트라 약 43억 개밖에 만들 수 없어 주소가 부족해짐, 128비트로 늘린 IPv6가 등장
  (IPv6는 주소만 많아진 게 아니라 보안, 품질 보장 기능도 기본으로 갖춤)

* IPv6 장점 : 주소의 확장성, 융토엉, 연동성 ^, 패킷 크기 제한 없음, 헤더 단순화로 처리 속도 ^, 서비스별 패킷 구분으로 품질 보장
* IPv6 축약 : 각 블록 앞자리 0 생략, 연솓된 0 블록은 ::로 한 번만 생략
  ex) 2001:0DB8:0000:0000:... -> 2001:DB8::...

2. 캐스팅 전송 방식
- 데이터를 몇 명에게 보내느냐에 따라 전송 방식이 달라짐
- 한 명에게만 보내면 유니캐스트, 특정 그룹에게 보내면 멀티캐스트, 같은 네트워크의 모드에게 뿌리면 브로드캐스트, 여러 후보 중 가장 가까운 한 곳에만 보내면 애니캐스트

* 유니캐스트(Unicast) : 일 대 일 통신 -> 단일 송신, 단일 수신(일반적인 웹 접속)
* 멀티캐스트(Multicast) : 일 대 다(그룹) 통신 -> 가입한 그룹에게만 전송(IPTV, 화상회의), 관리 프로토콜 IGMP
* 브로드캐스트(Broadcast) : 호스트가 속한 네트워크 전체를 대상으로 전송(ARP 요청) -> IPv4에만 있음
* 애니캐스트(Anycast) : 같은 주소를 가진 여러 노드 중 가장 가까운 한 노드와 일 대 일 통신 -> IPv6에서 도입(DNS, CDN)

3. IEEE 802 LAN 표준
- IEEE 802는 미국 전기전자학회(IEEE)가 정한 근거리 통신망(LAN), 도시권 통신망(MAN) 표준의 모음
- 번호마다 다루는 기술이 정해져 있어서, 시험에서는 번호 <-> 기술을 여녈하는 문제로 나옴
- 중요한 부분! 이더넷의 802.3(CSMA/CD)과 와이파이의 802.11(무선 LAN)

> IEEE 802 주요 표준
802.1    | 상위 계층의 인터페이스, 브리지, VLAN(802.1Q)
802.2    | 논리 링크 제어(LLC) 
802.3    | CSMA/CD(이더넷)
802.4    | 토큰 버스(Token Bus)
802.5    | 토큰 링(Token Ring)
802.6    | 도시형 통신망(MAN)
802.8    | 광섬유 LAN(Fiber Optic)
802.9    | 종합 음성, 데이터 네트워크
802.11   | 무선 LAN(Wi-Fi, CSMA/CA)
802.15   | 무선 PAN(블루투스, 지그비)

* CSMA/CD : 전송 전 회선이 비었는지 확인(Carrier Sense)하고, 전송 중 충돌을 감지(Collision Detection)하면 멈췄다가 임의 시간 후 재전송 -> 유선 이더넷
* CSMA/CA : 무선에서는 충돌 감지가 어려워 전송 전에 충돌을 회피(Collision Avoidanse)하도록 대기 -> 무선 LAN(802.11)
* 토큰 방식 : 토큰(전송 권한)을 가진 노드만 전송 -> 충돌 없음(토큰 버스, 토큰 링)

4. 애드혹 네트워크와 VLAN
보통 무선 기기는 기지국이나 공유기(AP)를 거쳐 통신, 재난 현장처럼 인프라가 없는 곳에서는 단말끼리 직접 연결 후 서로 중계해 멀리까지 전달하는 애드훅 네트워크 사용 반대로 사무실처럼 장비가 많은 곳에서는 스위치 설정만으로 LAN을 논리적으로 쪼개는 VLAN을 사용

* 애드훅 네트워크(Ad-hoc) : 기지국, 액세스 포인트 같은 네트워크 장치 없이 노드끼리 구성하는 네트워크
* 특징 : 모든 노드가 라우터 역할(멀티 홉 라우팅), 토폴로지가 동적으로 변화, 통신 거리 제약 극복
* 활용 : 긴급 구조, 긴급 회의, 전쟁터 군사 네트워크
* VLAN : 물리적 배치와 상관없이 논리적으로 LAN을 구성하는 기술 -> 스위치에서 포트, MAC 주소 등으로 그룹 지정(IEEE 802.1Q)
* 효과 : 브로ㄷ캐스트 도메인 분리로 불필요한 트래픽 감소, 접속 장비 성능 향상, 부서별 분리로 보안성 증대, 자리 이동 시 재배선 불필요


데이터링크, 네트워크 계층 프로토콜

1. HDLC와 데이터링크 프로토콜
- HDLC(High-level Data Link Control)는 가장 대표적인 데이터 링크 계층 프로토콜
- 데이터를 문자 단위가 아닌 비트 단위로 다루는 비트 동기 방식이라 어떤 형태의 데이터든 효율적으로 보낼 수 있음
- 프레임 앞뒤에 01111110 플래그를 붙여 시작과 끝을 표시, 끝부분의 FCS(CRC)로 오류 검사

* HDLC : 대표적인 데이터 링크 프로토콜, 비트 동기 방식, 단방향, 반이중, 전이중 모두 지원
* 관련 프로토콜 : BSC(문자 동기, 프레임에 전송 제어 문자 삽입), LAP-B(X.25 패킷 교환망), LAP-D(ISDN), PPP(전화전을 이용한 PC 간 연결), LLC(LAN)
* 링크 구성 : 불균형(주국 1 : 종국 다수) / 균형(혼합국 1 : 1)
  + 주국 : 명령을 보내 데이터 전송을 지휘, 종국 : 명령에 응답, 혼합국 : 명령과 응답을 모두 처리

2. HDLC 전송 모드와 프레임 종류
HDLC는 국들의 관계에 따라 세가지 동작 모드가 있음. 종국이 말하려면 주국의 허락이 필요한 NRM, 허락없이 먼저 보낼 수 있는 ARM, 두 혼합국이 대등하게 주고받는 ABM
프레임은 제어부 첫 비트로 정보, 감독, 비번호 세 종류 구분

전송보드        | 관계   | 특징
정규 응답(NRM)  | 불균형 | 종국이 데이터를 보내려면 주국의 허락이 필요(Normal Response Mode)
비동기 응답(ARM) | 불균형 | 종국 허락없이 데이터 전송 가능, 단 제어 기능은 주국만(Asynchronous Response Mode)
비동기 균형(ABM) | 균형  | 대등한 혼합국끼리 양쪽 모두 명령, 응답 전송 가능(Asynchrous Valanced Mode)       

프레임 종류   | 제어부 시작 | 역할
정보(I)프레임 | 0        | 사용자 데이터 전달, 송신 순서번호(Seq), 응답 순서번호(Next), P/F 비트
감독(S)프레임 | 10       | 확인 응답, 흐름제어, 오류 제어, 데이터 전송중이 아니라 Next만 존재, Type 2비트(4종류)
비번호(U)프레임| 11       | 순서 번호 없음, 링크 설정, 해제, 동작 모드 설정, Type 2비트 + Modifier 3비트

3. IP와 ICMP
IP는 데이터에 출발지, 목적지 주소를 붙여 목적지까지 보내는 인터넷의 핵심 프로토콜. 다만 "일단 보내고 보는" 비연결형, 비신뢰성 방식이라 패킷이 사라져도 스스로 알리지않음
그래서 전송 중 문제가 생기면 그 사실을 알려주는 조력자 ICMP가 함께 일함. ping 명령이 ICMP를 사용

* IP(Internet Protocol) : 전송할 데이터에 주소를 지정하고 경로를 설정
  + 비연결형 데이터그램 방식, 신뢰성 보장x(오류, 흐름 제어 없음), 패킷을 분할(단편화), 병합
  + 헤터 체크섬만 제공(데이터 체크섬x)
* ICMP(Internet Control Message Protocol) : IP와 함께 통신 중 오류 처리와 전송 경로 변경 등 제어 메시지를 관리, 헤더 8바이트
  + 대표메시지 : Echo Request / Reply(ping), 목적지 도달 불가, 시간 초과(traceroute), 경로 재지정
  + 악용 공격 : ICMP 패킷을 대량으로 보내는 PingFlooding, 스머프(Smurf) 공격

> IP와 ICMP의 역할 분담
구분        | IP                      | ICMP
열할        | 주소지정, 경로 설정, 패킷 전달 | 오류 보고, 진단, 제어 메시지
신뢰성       | 보장x(최선형 전달)          | IP의 부족한 오류 통보를 보완
예          | 모든 인터넷 패킷            | ping, traceroute
